# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This is a personal [Hyprland](https://wiki.hyprland.org/) (Wayland compositor) configuration. It is not a software project with a build system — Hyprland reads these files directly at runtime and reloads them automatically on save.

- [hyprland.conf](hyprland.conf) — main config: monitor setup, autostart (`exec-once`), env vars, `general`/`decoration`/`animations`/`dwindle`/`master`/`misc` blocks, input, and window rules. Started life as the distro-provided autogenerated example (see the header comment) and has been edited in place since.
- [keybind.conf](keybind.conf) — all keybindings, `source`-d into `hyprland.conf` at line 226. Custom binds are grouped near the top under `### MY HOTKEY ###`; below that is mostly untouched boilerplate from the example config (workspace switching, focus movement, multimedia keys).
- `scripts/` — helper shell scripts invoked from keybinds, e.g. [scripts/toggle-equibop.sh](scripts/toggle-equibop.sh) (toggles the Equibop client in/out of a special workspace via `hyprctl`), bound to `$mainMod SHIFT D`.
- `modules/` — currently just an empty `animation.conf`, not `source`-d anywhere; not part of the active config.
- [hyprlock.conf](hyprlock.conf), [hyprpaper.conf](hyprpaper.conf) — separate companion tools (screen lock, wallpaper daemon), not sourced by `hyprland.conf` but launched from it via `exec-once`.
- `hyprland.conf.bak`, `hyprland.conf.bak3` — manual backups, not read by Hyprland; ignore unless asked to diff/restore.

## Applying changes

Hyprland hot-reloads `hyprland.conf` and sourced files (`keybind.conf`) automatically on save — no restart needed. To manually reload: `hyprctl reload`.

There is no linter. Validate syntax by running `hyprctl reload` and checking for errors, or watching Hyprland's log for parse errors. Test keybind changes by pressing them; test `exec-once` changes by logging out/in (they only run once per session start) or invoking the command manually.

Waybar is restarted manually via `killall waybar && waybar -c ~/.config/waybar/config.jsonc -s ~/.config/waybar/style.css`, both at session `exec-once` and bound to `$mainMod SHIFT O` in [keybind.conf](keybind.conf). Waybar's own config lives in `~/.config/waybar/` and has its own [CLAUDE.md](../waybar/CLAUDE.md).

## Architecture notes

- **`$mainMod` is `Mod1` (Alt)**, not the more common `SUPER` — defined at the top of [keybind.conf](keybind.conf). Any new binding should reuse `$mainMod` rather than hardcoding a modifier, so a future remap only touches one line.
- **Two keyboard layouts**: `kb_layout = us,ru` with `kb_options = grp:win_space_toggle` (both in `hyprland.conf`'s top-level `input {}` and duplicated in the `### INPUT ###` section further down) — Win+Space toggles between them.
- **Duplicate `input {}` blocks**: there's a minimal `input {}` near the top (line 26, just layout/options) and a fuller one under `### INPUT ###` (line 196, adds `follow_mouse`, `sensitivity`, `touchpad`). Hyprland merges repeated blocks, but keep this in mind when editing input behavior — a setting could be sitting in either block.
- **Single monitor setup**: `monitor = DP-1,1920x1080@180,0x0,1` — hardcoded to one specific output name/resolution/refresh rate; adding a second monitor or moving to a different machine requires editing this line (check `hyprctl monitors` for the correct name first).
- **Window rules use the newer unified syntax** (`windowrule = match:class ^(...)$, <action>`) rather than the older `windowrulev2 = <action>, class:^(...)$` form seen in the commented-out examples further down — follow the `match:` style for new rules.
- Several lines/comments are in Russian (e.g. around lines 246–258, the animation slide-direction experiments) — these are commented-out scratch work from tuning per-app slide animations, safe to ignore or remove.
